# Contributing

Thanks for helping improve HOLBERY Marketplace.

## Ground rules
- Keep changes focused and explain the user/business problem.
- Do not include secrets, customer data, private HIO data, or Bozq One System information.
- Use original or properly licensed assets and record their licenses.
- Explain why new dependencies are necessary.
- Avoid production changes without explicit owner approval.
- Do not represent planned integrations as working.

## Branches and pull requests
Use descriptive branches such as docs/topic, feat/topic, or fix/topic. Keep PRs reviewable and include testing evidence. Document risks, migrations, and rollback steps. Never rewrite shared history unless explicitly authorized. The repository owner is the final approver for public release, pricing, policy, payment, and legal changes.

## Checks
Run relevant format, lint, type-check, unit/integration tests, and production build. If a check cannot be run, say so rather than claiming it passed.
